# AI-generated contributions

The crates in this directory were generated by an AI coding assistant, working under human direction.
They are kept apart from the rest of the workspace, and their rows in [ALGORITHMS.md](../ALGORITHMS.md) are marked "AI-generated".

| Crate | What it is |
|-------|------------|
| [embedded-cal-cryptocell](embedded-cal-cryptocell) | Back-end for Arm CryptoCell on the nRF5340 (CC312) and nRF52840 (CC310) |

## Risks

Generated code can look right and pass its tests while still being wrong.
Before relying on these crates, consider that:

- **Subtle bugs can survive the tests.**
  Tests cover the cases someone thought of.
  Code that was generated rather than written from understanding may fail on inputs nobody tested.
- **Security properties are hard to test.**
  Side-channel resistance, handling of secrets, and behaviour on malformed input don't show up as failing tests.
  A constant-time comparison, for example, can be compiled into one that leaks timing.
- **Hardware details may be inferred, not documented.**
  Where vendor documentation is incomplete, register behaviour may come from reading other code or from experiment.
  Behaviour outside what was tested may differ.
- **Review may be shallower than the code suggests.**
  Fluent, well-commented code invites less scrutiny than it deserves.
- **Provenance is less certain.**
  It is harder to establish where every idea in generated code came from.

## Maintenance

These crates are maintained by regenerating them, not by editing them line by line.
A crate may be regenerated in whole or in part, or heavily refactored, at any time.
A pull request that changes the code by hand may therefore become obsolete before it is merged, or soon after.

Bug reports are more useful than patches: an issue that describes the problem, ideally with a failing test, survives regeneration.
If you do send a patch, expect its idea, rather than its exact code, to be carried into the next version.

## Before using a crate from here

- Read its documentation for what has been verified, and on which hardware.
- Treat it as unreviewed until a maintainer has reviewed it as carefully as any hand-written cryptographic code.
- Run its tests on your own hardware.
- Report problems through the issue tracker, mentioning that the code is AI-generated.
